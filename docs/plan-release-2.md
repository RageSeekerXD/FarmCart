# План релізу 2.0 FarmCart: веб-інтерфейс (додаток до ЛР3)

Команда: 2 особи. Дедлайнів немає. Мова інтерфейсу: українська (за замовчуванням) + англійська; **дані каталогу також двомовні**. Ролі: покупець, фермер, кур'єр, адміністратор.

## 0. Прийняті рішення

| Рішення | Прийнято | Наслідок |
|---|---|---|
| Сховище | В пам'яті (`InMemoryStore`) + демо-дані при старті | Дані фермера зникають після перезапуску; обмеження зазначається в README. |
| Вхід | Достатньо `devCode`: API вже повертає код у режимі `ExposeSmsCodes` | На екрані входу в dev-режимі показуємо код і кнопку «підставити». Справжні SMS не потрібні. У Production це вже заборонено (захист у `Program.cs`). |
| Мова даних | **Українська дані при англійському інтерфейсі недопустимі** | Модель каталогу стає двомовною (BE-9); фермер вводить обидві мови; демо-дані містять обидві. |
| Фото товарів | Стокові з вільною ліцензією, автори в `docs/attributions.md`; запасна іконка за категорією | Ліцензійна чистота звіту. |
| Дедлайн | Немає | Урізання обсягу не планується; послідовність ітерацій визначається залежностями. |

### Межі двомовності

Двомовні **дані, якими керує система**: назви товарів, категорії, одиниці продажу, назви господарств, статуси замовлення й оплати, сповіщення, помилки.
**Не перекладається** текст, який вводять користувачі: відгуки, коментарі до замовлення, адреса, причина відхилення. Це зазначається в README.

## 1. Знахідки в коді, що впливають на план

| Знахідка | Наслідок |
|---|---|
| Bearer-токен (`Caller.BindAsync`) читає лише заголовок `Authorization`. | REST не змінюється; SignalR передає токен через `access_token`. |
| `FarmerDto` має `Lat/Lon`; `/catalog` приймає `lat/lon/maxKm`. | Мапі потрібні публічний список ферм і `distanceKm`. |
| `Product.Name/Category/Unit`, `Farmer.Name` - один рядок українською; `CatalogService` шукає й сортує за українською (`UkrainianOrder`); `OrderLine` і `CartLineView` копіюють `Name`/`Unit`. | Двомовність зачіпає Core, каталог, кошик, замовлення й ~10 файлів тестів (BE-9). |
| `Category` - довільний рядок, яким фільтрують («Овочі»). | Перекладати вільний текст неможливо, тому категорії й одиниці стають довідниками з кодами. |
| `INotifier.Push(userId, string text)`, `StatusTitle`, `PaymentTitle`, тексти помилок - лише українські. | Фронтенд локалізує за кодами; сповіщення структуруються (BE-2). |
| `DemoData.Seed`: 4 ферми, 9 товарів, без фото й відгуків. | Недостатньо; потрібні BE-8 і англійські назви. |
| Node.js на машині немає. | Node 22 LTS на обох машинах і в `ci.yml`. |
| Є `IClock`; історія DEF-03 (демо працювало лише в серпні-жовтні). | E2E і демо-дані не залежать від місяця. |

## 2. Архітектура та стек

- React 19 + TypeScript + Vite, папка `web/`.
- React Router, TanStack Query, react-i18next (`uk`/`en`, вибір у `localStorage`), MUI.
- Мапа: react-leaflet + OpenStreetMap (з атрибуцією).
- Реальний час: `@microsoft/signalr`.
- Типи API: OpenAPI з бекенду + `openapi-typescript`.
- Dev: Vite проксує `/api` і `/hubs` на `:5080`. Прод: `FarmCart.Api` віддає `web/dist` статикою.

### BE-9. Двомовні дані (TDD: приймальний тест → red → green → рефакторинг)

- **Тип `LocalizedText(Uk, En)`**; обидва поля обов'язкові й непорожні.
- **Product:** `Name` і `Unit` - `LocalizedText`; **Farmer:** `Name` - `LocalizedText`.
- **Довідники з кодами** (`GET /api/reference`): категорії (`vegetables`, `fruits`, `berries`, `dairy`, `honey`, `meat-eggs`, `bakery`) й одиниці (`kg`, `l`, `kg-0.5`, `jar-0.5l`, …), кожна з `uk`/`en`. `ProductDraft.Category` і `Unit` - коди з довідника, невідомий код дає помилку валідації.
- **Знімки в замовленні:** `OrderLine` і `CartLineView` зберігають `LocalizedText` для назви й одиниці, щоб історія замовлень була англійською після зміни товару.
- **Каталог:** текстовий пошук (`q`) шукає в обох мовах; сортування за назвою залежить від нового параметра `lang=uk|en` (укр. колація для `uk`, інваріантна для `en`); фільтр `category=` приймає код.
- **Контракт:** DTO віддають обидві мови, фронтенд обирає потрібну. Це **змінює HTTP-контракт**, тому випуск 2.0.0 і нотатка в README/журналі змін.
- **Тести:** наявні тести оновлюються механічно через допоміжні методи в `TestWorld`; нові тести: пошук англійською, сортування за `lang`, відхилення порожньої англійської назви, знімок англійської назви в замовленні.

### BE-8. Демонстраційні дані

- **Ферми:** 10-12 по Львівщині, різні сертифікації й координати; 2 у черзі верифікації; усі з `Name.En`.
- **Товари:** 40-50 позицій у 7 категоріях; ≥ 60 % цілорічних (каталог не порожній у жодному місяці); кілька з `Stock = 0`; усі з англійською назвою.
- **Фото:** `src/FarmCart.Api/wwwroot/img/products/`, автори в `docs/attributions.md`.
- **Історія:** відгуки; по одному замовленню в кожному статусі для демо-покупця.
- **Тести (`DemoDataTests`):** ≥ 20 товарів у кожному місяці; усі категорії представлені; **жодне англійське поле не містить кириличних символів**; кожен `PhotoUrl` вказує на існуючий файл і є в `attributions.md`.
- Сценарій `demo.cmd` (цілорічні товари) проходить без змін.

## 5. Ітерації та розподіл

A - фронтенд; B - бекенд і частина фронтенду. Ролі умовні. Дедлайнів немає, тож ітерація завершується, коли виконано критерії готовності й пройдено CI.

| Ітерація | Людина A | Людина B |
|---|---|---|
| **0. Каркас** | Vite + TS, i18n, роутінг за ролями, MUI-тема | Node у CI, OpenAPI → типи, статика (BE-5) |
| **1. Двомовні дані й пошук** | UI-01; UI-02 (спершу на MSW-моках, потім на реальному API) | **BE-9**, потім BE-8, BE-1 |
| **2. Мапа й кошик** | UI-03, UI-04 | BE-2 |
| **3. Замовлення** | UI-05, UI-06 | UI-07, доробка помилок |
| **4. Постачальники** | UI-10 | UI-08, UI-09 |
| **5. Реальний час** | UI-12 (клієнт) | BE-3, BE-4 |
| **6. Адмін і реліз** | UI-11, e2e | BE-6, BE-7, документація, тег `2.0.0` |

Критичний шлях: BE-9 → BE-8 → UI-02. Поки BE-9 не злито, A працює з моками, форма яких узгоджена заздалегідь (DTO із `LocalizedText`).

## 6. Тестування та CI

- **Компоненти:** Vitest + Testing Library + MSW (форми, фільтри, i18n, помилки).
- **Двомовність:** тест на збіг ключів `uk.json`/`en.json`; компонентні тести в обох мовах.
- **Мапа:** відстань, межі, сортування - чисті функції з юніт-тестами; Leaflet-картинку автоматично не тестуємо.
- **E2E (Playwright):** справжній API з демо-даними й фіксованим часом: покупець купує → фермер приймає → кур'єр вручає → покупець бачить статус без перезавантаження. Окремий сценарій англійською: на сторінках каталогу, кошика й замовлень немає кирилиці.
- **`ci.ps1`:** додаємо `npm ci`, `eslint`, `tsc --noEmit`, `vitest --coverage` (поріг 70 %), `vite build`, Playwright; кроки .NET лишаються.
- **Докази:** `docs/evidence/ui/…` у форматі попередніх ЛР; знімки екранів ключових сценаріїв обома мовами.

## 8. Ризики

1. **BE-9 зачіпає багато файлів** (Core, API, ~10 файлів тестів) і змінює HTTP-контракт. Робимо першою окремою невеликою серією комітів, CI має лишатися зеленим на кожному кроці.
2. **SignalR + токен у query:** `UseRequestLog` пише лише шлях, але потрібен тест, що токен не потрапляє в журнал.
3. **Ліцензії фото:** кожне фото в `attributions.md`; тест із BE-8 це перевіряє.
4. **Фермер мусить вводити дві мови:** це незручність форми, але вимога заказчика. Підказка в UI, що англійська назва потрібна для англомовних покупців.
5. **Сховище в пам'яті:** дані фермера не переживають перезапуск; зазначено в README.
6. **Tiles OSM:** обов'язкова атрибуція, мінімальне навантаження під час демо.
7. **Playwright і Smart App Control:** перший запуск може вимагати дозволу.
